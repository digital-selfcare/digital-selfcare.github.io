# 📖 РУКОВОДСТВО ПО САМОСТОЯТЕЛЬНОМУ УПРАВЛЕНИЮ САЙТОМ ЧЕРЕЗ GITHUB

Это руководство создано для того, чтобы вы могли **самостоятельно и без участия разработчика** управлять контентом вашего сайта: менять любые тексты, добавлять или удалять новости, загружать фотографии участников и прикреплять новые файлы (PDF, Word, Excel) для скачивания в разделе «Материалы».

Все действия выполняются прямо в браузере через сайт **GitHub.com** — вам не нужно устанавливать никаких специальных программ или писать код!

---

## 🧭 ГЛАВА 1. ГДЕ ХРАНИТСЯ КОНТЕНТ САЙТА

Весь текстовый контент сайта сосредоточен в одном файле:
📌 **`src/content.js`**

Этот файл представляет собой структурированную базу данных. Он написан на простом языке JavaScript, но устроен как обычный список параметров.

### ⚠️ Золотые правила безопасности при редактировании `src/content.js`
Чтобы сайт не «сломался» при сборке, всегда соблюдайте три простых правила:
1. **Кавычки**: Любой текст должен быть заключен в двойные кавычки: `"Мой текст"`. Не удаляйте кавычки по краям текста. Если внутри вашего текста тоже нужна кавычка, используйте «елочки» — `"Статья «Здоровье россиян»"`.
2. **Запятые**: Все параметры, строки и блоки в списках разделяются запятыми. Забытая запятая — самая частая причина, почему сайт перестает собираться.
3. **Скобки**: 
   - Фигурные скобки `{ ... }` обозначают «карточку» объекта (например, конкретного участника или новость).
   - Квадратные скобки `[ ... ]` обозначают список из нескольких элементов (например, список публикаций участника).

## 🛠 ГЛАВА 2. ПОШАГОВЫЕ ИНСТРУКЦИИ

### 1️⃣ Редактирование существующих текстов (например, имени или биографии)
Если вам нужно исправить опечатку, изменить звание, обновить адрес или email:

1. Зайдите в ваш репозиторий на **GitHub.com**.
2. Перейдите по папкам: **`src`** $\rightarrow$ нажмите на файл **`content.js`**.
3. В правом верхнем углу файла нажмите на **иконку карандаша** (`Edit this file`) — откроется текстовый редактор.
4. Найдите нужную строчку (например, `name: "Шляпина Анастасия Сергеевна"` или `email: "natnes@list.ru"`).
5. Измените текст внутри кавычек. **Важно:** не трогайте название параметра слева (например, `name:` или `email:`).
6. Прокрутите страницу до самого низа.
7. В блоке **Commit changes** (Сохранить изменения):
   - В поле заголовка напишите кратко, что вы сделали (например: *«Исправила email контактов»*).
   - Нажмите зеленую кнопку **Commit changes** внизу.
8. **Готово!** Автоматическая система сама соберет сайт заново и обновит его в сети в течение 1 минуты.

---

### 2️⃣ Управление разделом «События и новости»
Новости отображаются на главной странице (3 самые свежие) и в специальном архиве.

#### Как добавить новую новость:
1. Откройте файл **`src/content.js`** в режиме редактирования (как в инструкции 1).
2. Найдите блок `events: { title: "События и новости", items: [` (примерно 14-16 строка).
3. Скопируйте одну из существующих новостей (вместе с фигурными скобками и запятой после закрывающей скобки) и вставьте ее **в самый верх списка** сразу после квадратной скобки `[`:

```javascript
      {
        id: "event-5", // Задайте уникальный ID (например: event-5, event-6 и т.д.)
        title: "Заголовок вашей новой новости",
        date: "21 мая 2026", // Дата публикации
        type: "Новости", // Тип: "Новости", "Публикации", "Мероприятия" или "Методология"
        image: "news/имя_фотографии.png", // [НЕОБЯЗАТЕЛЬНО] Картинка в папке public/news/
        description: "Краткое описание новости. Оно будет отображаться на плитке на главной странице.",
        content: "Полный подробный текст новости. Он откроется во всплывающем окне, когда пользователь нажмет на кнопку «Подробности»."
      }, // <-- Не забудьте запятую в конце фигурной скобки!
```

4. Отредактируйте параметры `id`, `title`, `date`, `description`, `content` и `image` под вашу новую новость.
5. Нажмите кнопку **Commit changes** внизу для сохранения.

#### 🖼 Как привязать картинку (фотографию) к новости:
Если вы хотите, чтобы при открытии полной новости внутри отображалась красивая иллюстрация (например, фото награждения, обложка статьи или баннер круглого стола):
1. **Загрузите картинку на GitHub**:
   - Перейдите по папкам: **`public`** $\rightarrow$ **`news`**.
   - В правом верхнем углу нажмите кнопку **Add file** $\rightarrow$ **Upload files**.
   - Перетащите файл картинки в окно браузера (например, `Shlyapina_Stipend1.png`).
   - Нажмите зеленую кнопку **Commit changes** внизу.
2. **Укажите путь к картинке в `src/content.js`**:
   - Вставьте в блок вашей новости параметр `image` с указанием пути к загруженному файлу:
     `image: "news/Shlyapina_Stipend1.png",`
   - Если картинка для конкретной новости не требуется, эту строку можно просто пропустить или удалить — новость откроется с текстовым оформлением по умолчанию.

#### Как удалить новость:
Просто выделите блок новости от открывающей фигурной скобки `{` до закрывающей `},` (включая запятую) и удалите его из файла `src/content.js`. Сохраните изменения кнопкой **Commit changes**.

### 3️⃣ Управление фотографиями участников (Команда)
Если к вам присоединился новый участник или вы хотите заменить существующую фотографию:

#### Шаг А. Загрузка фотографии в хранилище сайта:
1. В репозитории на GitHub перейдите в папку **`public`** $\rightarrow$ **`team`**.
2. В верхнем правом углу нажмите кнопку **Add file** $\rightarrow$ **Upload files**.
3. Перетащите файл новой фотографии в окно браузера (или выберите на компьютере).
   - *Рекомендация*: Называйте файл латинскими буквами в формате `фамилия-имя.jpg` (например, `shlyapina-anastasia.jpg`). Поддерживаются форматы `.jpg`, `.jpeg`, `.png`.
4. Внизу нажмите кнопку **Commit changes** для сохранения фотографии в репозитории.

#### Шаг Б. Привязка фотографии к участнику в `src/content.js`:
1. Откройте файл **`src/content.js`** в режиме редактирования.
2. Найдите нужного участника команды по его `id` или имени (например, блок Анастасии Шляпиной).
3. Измените параметр `image` на имя загруженного файла, добавив перед ним `team/`:
   `image: "team/shlyapina-anastasia.jpg",`
4. Сохраните изменения нажатием на кнопку **Commit changes**.

### 4️⃣ Загрузка файлов и добавление в раздел «Материалы»
Мы автоматизировали кнопку **«СКАЧАТЬ»**! Теперь вы можете загружать файлы прямо на сайт, и пользователи смогут их скачивать в один клик.

#### Вариант А. Загрузка файла напрямую в хранилище сайта (для PDF, DOCX, XLSX и т.д.):
1. В репозитории на GitHub перейдите в папку **`public`** (это корневое хранилище файлов).
2. Нажмите **Add file** $\rightarrow$ **Upload files**.
3. Загрузите ваш документ. Старайтесь использовать лаконичные имена файлов латиницей или кириллицей **без пробелов** (заменяйте пробелы на подчеркивание `_`), например: `Protocol_interview.pdf` или `Anketa_v2.docx`.
4. Нажмите кнопку **Commit changes** внизу.
5. Теперь откройте файл **`src/content.js`** в режиме редактирования.
6. Найдите нужную категорию материалов (например, `id: "methodology"`) и в список `files` добавьте информацию о вашем файле:

```javascript
          { name: "Protocol_interview.pdf", size: "1.2 MB", date: "21.05.2026" }
```

> [!IMPORTANT]
> Параметр `name` должен **символ в символ** совпадать с именем загруженного в папку `public` файла. Сайт автоматически найдет его и скачает!

7. Сохраните изменения через кнопку **Commit changes**.

#### Вариант Б. Если файл лежит на внешнем диске (Яндекс.Диск, Google Drive, Облако Mail.ru):
Если файлы слишком большие (больше 20 МБ), не загружайте их на GitHub, а используйте ссылку на облако:
1. Загрузите файл на свой Яндекс.Диск или Google Drive и скопируйте публичную ссылку на него.
2. Откройте **`src/content.js`** и добавьте параметр `url` к описанию файла:

```javascript
          { 
            name: "Массив опроса на Яндекс Диске.xlsx", 
            size: "Внешняя ссылка", 
            date: "21.05.2026", 
            url: "https://disk.yandex.ru/d/ваша_ссылка" 
          }
```

Сайт увидит параметр `url` и при клике на «СКАЧАТЬ» перенаправит пользователя прямо на ваше облако!

## 🖼 ГЛАВА 3. ПОДГОТОВКА И СОХРАНЕНИЕ КАРТИНОК И ФОТОГРАФИЙ ДЛЯ САЙТА

Чтобы все иллюстрации, сканы документов и фотографии отображались на сайте идеально четко и быстро загружались как на компьютерах, так и на смартфонах, следуйте этим рекомендациям при подготовке изображений:

### 1. Форматы файлов: когда какой использовать?
*   📸 **`.jpg` / `.jpeg`** — используйте для **обычных фотографий** (портретов команды, репортажных снимков с мероприятий). Этот формат отлично сжимает естественные цвета и детали.
*   📄 **`.png`** — используйте для **документов, таблиц, списков, скриншотов с текстом или графикой** (например, скан приказа о стипендии, графики Wordstat, логотипы). PNG сохраняет абсолютную четкость линий и текста без размытия, которое бывает в JPG.

### 2. Оптимальный размер и разрешение (Сжатие)
Загружать картинки весом в 5–15 МБ прямо с фотоаппарата или телефона **категорически не рекомендуется** — сайт будет долго грузиться у мобильных пользователей.
*   ⚖️ **Вес файла**: старайтесь сжимать картинки так, чтобы они весили **до 500 КБ** (максимум 1 МБ).
*   📐 **Разрешение (размер в пикселях)**:
    *   Для новостных иллюстраций и документов: около **1200 пикселей по ширине**.
    *   Для портретов команды (вертикальные/квадратные): около **800 пикселей по высоте/ширине**.

### 3. Как быстро подготовить и сжать картинку без сложных программ?
Если у вас есть огромная фотография или скан:
1.  **Кадрируйте и измените размер**: в стандартном приложении «Фотографии» на Windows или любом другом редакторе уменьшите разрешение картинки до ~1200 пикселей по ширине.
2.  **Сожмите для Web**: используйте бесплатные онлайн-сервисы сжатия без потери качества, например [TinyPNG / TinyJPG](https://tinypng.com/) или [ILoveIMG](https://www.iloveimg.com/ru). Просто перетащите туда файл и скачайте сжатую версию, которая будет весить в 5-10 раз меньше!
3.  **Латинские имена**: всегда сохраняйте файлы с именами латиницей без пробелов и спецсимволов (используйте нижнее подчеркивание `_` или дефис `-`), например: `Shlyapina_Stipend_President.png`.

## 📈 ГЛАВА 4. ПРОВЕРКА ОШИБОК И СТАТУС СБОРКИ

Каждый раз, когда вы нажимаете кнопку **Commit changes** на GitHub, запускается автоматическая сборка вашего сайта (GitHub Actions). Процесс сборки занимает около 1-2 минут.

### Как проверить, все ли в порядке:
1. В верхней панели репозитория на GitHub перейдите на вкладку **Actions**.
2. В списке вы увидите строчку с названием вашего сохранения (например, *«Исправила email контактов»*).
3. Рядом со строчкой будет отображаться значок статуса:
   - **Желтый кружок**: Сайт собирается прямо сейчас. Подождите около минуты.
   - ✅ **Зеленая галочка**: Сайт успешно собран и обновлен! Вы можете открыть сайт и увидеть изменения.
   - ❌ **Красный крестик**: Произошла ошибка. Сайт **НЕ** обновился. 

### Что делать, если горит красный крестик?
Если загорелся красный крестик, значит, при редактировании `src/content.js` была допущена синтаксическая ошибка (например: стерли кавычку, забыли поставить запятую или случайно удалили фигурную скобку).

**Как быстро починить:**
1. Нажмите на ошибочную строчку с красным крестиком в **Actions**.
2. Вы увидите логи сборки, где будет написано, например: `SyntaxError: Unexpected token ... in content.js` с указанием номера строки, где допущена ошибка.
3. Откройте файл `src/content.js`, найдите эту строку, исправьте ошибку (добавьте запятую или закройте кавычку) и снова нажмите **Commit changes**. Сборка запустится заново и загорится зеленым цветом!
